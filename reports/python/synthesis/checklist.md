# Canonical Python language-feature checklist

## Scope and baseline

This checklist reconciles the Codex (`C`), Claude Fable (`F`), and Google Deep Research (`G`) reports. It is intentionally neutral about project theme and implementation design.

- **Canonical baseline:** Python 3.13 language semantics on CPython 3.13. Python 3.8–3.12 behavior is retained through explicit version variants. Python 3.14-only claims are research gaps until checked against final 3.14 primary documentation.
- **Packaging baseline:** standards-based `pyproject.toml` builds through a Python Packaging Authority (PyPA) build frontend and backend. Backend-, installer-, checker-, test-runner-, platform-, and alternative-interpreter behavior is conditional.
- **Status:** `required` means every complete fixture set must demonstrate the behavior. `conditional` means a separate configuration, artifact, platform, implementation, or selected ecosystem lane is needed. Unverified claims appear only under **Unresolved research gaps**.
- **Classification:** `language-defined` includes normative Python language and documented standard-library contracts. `implementation-defined` is CPython- or host-specific. `unspecified` means portable code must not assert one result. `ecosystem convention` covers packaging and external-tool contracts.
- **Provenance:** `C`, `F`, and `G` identify the reports that proposed the materially same behavior. Provenance does not imply a vote.

## Version and configuration matrix

| Version/configuration | Material boundary represented by checklist |
| --- | --- |
| Python 3.8 | Assignment expressions, positional-only parameters, f-string debug expressions, standard-library protocols/typed dictionaries/final intent, audit hooks, and relevant parse failures on older versions. |
| Python 3.9 | Built-in collection generics, arbitrary decorator expressions, dictionary merge operators, and newer resource APIs. |
| Python 3.10 | Structural matching, union operators, parameter specifications, type guards, and soft-keyword grammar. |
| Python 3.11 | Exception groups/star handlers, task groups, `Self`, variadic generics, overload introspection, dataclass transforms, enum additions, and removal/version diagnostics. |
| Python 3.12 | PEP 695 type parameters/type aliases, PEP 701 f-strings, `@override`, Python-level buffer export, monitoring, comprehension implementation changes, and removed legacy library modules. |
| Python 3.13 baseline | Defined `locals()` behavior, type-parameter defaults, `TypeIs`, newer TypedDict intent, experimental free-threaded/JIT builds, and further removals. |
| Python 3.14 | Deferred annotations, template strings, subinterpreters, free-threading maturity, and default-start-method claims remain gaps rather than baseline facts. |

Mutually exclusive states require separate fixtures or runs: regular versus implicit/legacy namespace resolution for one name; flat versus `src` layout for one distribution; eager versus future-stringized versus 3.14-lazy annotations in one module; source-tree versus regular versus editable versus bundled execution; normal versus optimized/debug/free-threaded/JIT CPython builds; platform-specific import/filesystem/process lanes; hash seeds; multiprocessing start methods; typed versus untyped/stubbed installed artifacts; and dependency/extras/resolver environments.

### Unsupported or corrected claims

- Google's label “AST synthesized methods” for dataclasses and named tuples is corrected: generation occurs through documented decorators/factories and runtime class construction, not by a general Abstract Syntax Tree (AST) synthesis contract. The verified obligations are `PY-CAN-OBJ-013` and `PY-CAN-OBJ-015`.
- Google's claim that PEP 561 makes every checker “completely ignore” unmarked inline annotations is too absolute. `PY-CAN-TYPE-016` requires marker-present, marker-absent, stub, and configured-checker variants without prescribing a single tool outcome beyond the typing/distribution specification.
- Google's claim that a graph “must” evaluate arbitrary `__all__`, dynamic imports, or editable `.pth` code is not a Python semantic requirement. The checklist requires observable constant and dynamic cases, plus an explicit unresolved result when safe static resolution is impossible.
- Fable's precise Python 3.14 multiprocessing-default and free-threading-maturity statements remain unsupported in the supplied primary evidence and are covered by `PY-GAP-004`/`PY-GAP-010`.

## Completeness audit

### Input-report items omitted or merged

- All Codex candidates through `PY-INT-008` were retained, merged only with materially identical Fable/Google proposals. Two were not promoted to required/conditional rows: 3.14 template strings (`PY-SRC-016`) moved to `PY-GAP-002`, and rapidly evolving lock files/dependency groups (`PY-PKG-016`) moved to `PY-GAP-005`.
- Fable's 126 report-local items were retained or merged. `FUN-06`, `FUN-11`, `DYN-02`, `DYN-03`, `DYN-06`, `PKG-12`–`PKG-14`, `TST-05`, `ERR-04`–`ERR-07`, and `ECO-01`–`ECO-06` remain explicit canonical rows because Codex had no materially identical standalone item. Framework examples were generalized so the checklist does not select Flask, Click, Django, SQLAlchemy, Pydantic, or another theme.
- Google proposed 16 detailed items. Every item maps to required or conditional rows: namespace packages (`MOD-003/004`), layouts (`MOD-016`, `PKG-005`), exports (`MOD-008`), build metadata/editables (`PKG-002/003/011`), dynamic imports (`MOD-013`), metaclasses/MRO/descriptors (`OBJ-001/003/006`), mangling/matching/generated records (`BIND-011`, `PROT-011`, `OBJ-013/015`), and typing (`TYPE-001/004–006/016/021`). Its three stated gaps map to `PY-GAP-007`, `OBJ-003`, and `TYPE-016`; schema/product-specific wording was omitted because the synthesis has no downstream context.
- No item was omitted because it appeared in only one report. Single-source plausible items are retained as required/conditional when backed by a named primary contract, or as a gap when evidence was weak.

### Categories represented by only one source

- Predominantly Codex-only: buffer protocol; detailed numeric/container dispatch; reload; low-level C ownership/thread state; direct-URL metadata; externally managed environments; reproducible builds; audit/monitoring hooks; most filesystem/time/subprocess edges; cross-feature interaction rows.
- Predominantly Fable-only: partial/partialmethod; wrapper caching; explicit dotted-string references; workspace and PEP 723 script metadata; mock “where to patch”; accidental redefinition/star collision; documentation, ORM-style, and command-dispatch conventions.
- Google-only categories: none. Google's unique contribution is cited primary-source emphasis and deeper evidence for selected import, packaging, object-model, pattern, and typing items.

### Weak or missing primary evidence

- Current 3.14 language/library behavior, free-threaded/JIT build contracts, subinterpreters, lock/dependency-group standards, and latest typing-spec extensions remain weak. They are isolated in `PY-GAP-001`–`PY-GAP-006`.
- Backend, resolver, workspace, test runner, checker, documentation tool, transpiler, freezer, and framework rows cite the governing standard plus require the selected tool's primary documentation. No one tool was selected by the reports, so tool-specific expectations cannot be canonical yet.
- Alternative implementations and host-platform lanes need target-owned documentation before asserting outcomes. CPython behavior is not silently generalized.
- The Google report's citation set includes many secondary sources and redirect links. This synthesis cites the primary language, standard-library, PEP, typing, and PyPA sources named or supported by the reports and does not rely on secondary-source claims to promote an item.

### Likely blind spots for another research pass

- Notebook/cell execution, magics, and out-of-order state.
- Embedding Python in a native host, mobile/WebAssembly runtimes, and per-interpreter extension safety.
- Internationalization message catalogs and string-key references.
- Conda/operating-system package ecosystems, vendored wheels, supply-chain attestations, license-expression transitions, and current standard lock files.
- Scientific dispatch such as array coercion/universal functions, serialization frameworks, and framework-specific generated APIs.
- Property-based/fuzz/mutation testing, continuous-integration matrices, documentation builds that execute imports, and type-checker plugins. These are not promoted without a distinct semantic contract and primary evidence.
