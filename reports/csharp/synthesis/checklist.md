# Canonical C# Language-Feature Checklist

## Scope and interpretation

This document reconciles the Codex (`C`), Fable (`F`), and Google Deep Research (`G`) reports. It defines coverage obligations, not a project theme or source design.

- **Baseline:** stable C# 13, Roslyn in the .NET 9 Software Development Kit (SDK), SDK-style MSBuild, NuGet `PackageReference`, and Core Common Language Runtime (CoreCLR). Earlier versions remain required where a version boundary changes observable behavior.
- **Status:** **required** means the behavior belongs in broad C# coverage. **conditional** means it needs a separate project, build, target, platform, dependency, or configuration and is required when that condition is represented. **unresolved research gap** is kept outside the required checklist.
- **Classification:** the classification names the controlling contract: **language-defined**, **implementation-defined**, **unspecified**, or **ecosystem convention**. A row may mention secondary runtime or tool constraints without changing that primary classification.
- **Citations:** citations point to primary specifications or official tool documentation. The reports' secondary citations are not used to settle conflicts.

## 9. Completeness audit

### Input-report items omitted or relocated

- No materially distinct stable item was silently dropped. Closely related proposals were merged only when the observable behavior was the same. Examples: Codex's type-kind and Fable's enum/delegate rows were split where behavior differed; Fable's package rows were consolidated by NuGet asset-selection behavior; Google's 15 feature rows map to canonical rows or explicit gaps.
- Fable's incorrect claim that top-level statements plus explicit `Main` are a duplicate-entry-point error was omitted. The canonical item follows the top-level-statements specification: the explicit entry point is ignored and warned about.
- Google's recommended .NET 8/C# 12 baseline was omitted as product guidance, not a feature. The reports otherwise center stable C# 13/.NET 9, while version boundaries are explicit per item.
- Google's claim that every generator project must target .NET Standard 2.0 was narrowed in CS-CAN-015 and preserved as CS-GAP-006 because the supplied primary evidence does not establish universality.
- Google's abstract-plus-extern observation was not given a standalone item. It is an ordinary invalid modifier combination covered by error/configuration cases and has no separate materially observable resolution behavior.
- Commentary about code-graph architecture, project themes, and which technology is “paradigm-shifting” was omitted because it is downstream context, not C# behavior.
- C# 14, interceptors, scripts/file-based apps, legacy tooling, rare metadata, and other medium-confidence audit proposals were relocated to CS-GAP-001 through CS-GAP-013 rather than promoted without primary verification.

### Categories represented by only one report

- Fable alone proposed project-reference graphs, central package management/lock files, source-distributing packages, cross-language consumption, query translation as its own item, test discovery, specific framework generators, solution composition, and several ecosystem conventions. They remain conditional canonical items because each has a distinct observable boundary and a named official primary-source family.
- Codex alone developed arrays, nullable value lifting, native-sized integers, exception filters, detailed lifetime/stack allocation, deterministic unspecified behavior, platform compatibility, and compiler breaking-change matrices at canonical-item depth.
- Google alone emphasized MSBuild `Choose` syntax as a named construct, but it is materially the same conditional-evaluation behavior as conditional property/item groups and is merged into CS-CAN-100.

### Weak or missing primary evidence

- The Google report labels itself citation-backed, but most linked sources are secondary articles, videos, or redirect URLs. Only official Microsoft links can act as primary evidence, and even those do not cover all assertions attached to them.
- The Codex and Fable reports usually name the correct primary specification family but do not provide section-level URLs. Canonical citations therefore identify the primary source and topic; a verification pass should replace broad feature-spec index citations with the exact adopted specification page and section.
- Exact historical Roslyn diagnostics, default implicit-using sets, generator loading, design-time builds, package conflict tie-breaks, COM/NoPIA, XAML/workload generation, and C# 14 details remain weakly evidenced.

### Likely blind spots for another research pass

- Resolve every CS-GAP item against the exact supported SDK/compiler/runtime matrix, starting with stable C# 14 specifications and interceptors.
- Add a section-by-section crosswalk against the current C# specification and adopted feature-spec index. Then test rare metadata consumption and legacy/alternate runtime behavior separately.
- Perform focused primary research on the CLI/.NET memory model, design-time MSBuild evaluation, NuGet restore conflict rules, workload-generated source, and publish transforms.
- Decide explicit scope for runtime-only linkage and mutation: assembly load contexts, reflection emit, IL weaving, serialization/Dependency Injection conventions, and framework discovery.
